# 领域文档

说明工程技能在探索代码库时如何使用本项目的领域文档。

## 探索前读取

- 根目录的 `CONTEXT.md`；或
- 如果根目录存在 `CONTEXT-MAP.md`，读取它指向的、与当前主题相关的各个 `CONTEXT.md`
- 读取与即将修改区域相关的 `docs/adr/` 中的 ADR

如果这些文件不存在，静默继续，不要提示缺失，也不要主动建议立即创建。`/domain-modeling` 技能会在术语或决策实际确定时按需创建它们。

## 文件结构

本项目采用单上下文结构：

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-示例决策.md
│   └── 0002-示例决策.md
└── src/
```

## 使用术语表中的词汇

当输出中出现领域概念（议题标题、重构提议、假设、测试名称等）时，使用 `CONTEXT.md` 中定义的术语。不要使用术语表明确避免的同义词。

如果所需概念尚未出现在术语表中，这说明需要重新考虑是否正在创造项目没有使用的语言；若确有缺口，应记录下来交给 `/domain-modeling` 处理。

## 标记 ADR 冲突

如果输出与现有 ADR 冲突，应明确指出，而不是静默覆盖：

> 与 ADR-0007 冲突（示例决策），但由于……值得重新审议。
